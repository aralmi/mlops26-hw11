# ДЗ 11. Сервис работает, пользователи ждут

Сервис из [ДЗ 8–10, commit 5ee53dc](https://github.com/aralmi/mlops26-hw8-9-10/tree/5ee53dcc1661ceb51d9a4dabc3154270738d34d6) продолжен в Kubernetes. Сохранены HTTP-маршруты и проверка фактически загруженной версии. Добавлены NDJSON-стриминг, подготовка Pod, ограниченная очередь, локальный кеш префиксов и метрики. Ответы помечены `backend_mode=simulated`. В этой работе `max_new_tokens` ограничивает число частей ответа, а измеряемая задержка называется TTFC.

Условия в [assignment.html](assignment.html), подробности опытов в [report.html](report.html). Откройте HTML локально в браузере вместе с папкой `results`.

## Запуск

Нужны Docker Desktop, kind v0.30.0, Helm v3.18.6, kubectl v1.34.0, Python 3.12 и uv для пересборки графиков. Подготовьте не менее 7 GiB диска и не менее 4 GiB RAM для Docker. Проверенный стенд использовал Docker с 8 CPU и 7,65 GiB RAM. Инвентаризация и замер фактического размера лежат в `results`.

```sh
make setup
make overview
make health
make predict
```

Кластер `mlops-hw11` использует отдельный kubeconfig `.local/kubeconfig`. В namespace `hw11` находятся обе политики Service, приложение, клиенты и мониторинг. Pod читают артефакт из ConfigMap и сверяют SHA-256 и версию. CPU/RAM мониторинга ограничены в манифестах. Образы закреплены версиями и дайджестами.

Для Grafana запустите в отдельном терминале `make grafana`, откройте [дашборд](http://127.0.0.1:3000/d/mlops-hw11). Для Prometheus выполните `make prometheus`, откройте [правила алертов](http://127.0.0.1:9090/alerts).

## Опыты и проверка

Запускайте по очереди. Прогоны меняют число и версии Pod в выделенном кластере.

```sh
make check-live
make balance
make autoscale
make report
```

`make check-live` выполняет опыт A и пять проверок. `make check` проверяет сохранённые HTTP-результаты и журналы. `make balance` проводит 12 фаз по 120 секунд плюс замена Pod и снятие метрик. При повторном вызове завершённые повторы берутся из `results/balance/*/summary.json`. Чтобы повторно измерить серию, предварительно сохраните исходные результаты и уберите соответствующие папки из `results/balance`. `make autoscale` сохраняет CPU, HPA, Ready и переходы алертов. Для повторов выберите свободный от других задач кластер.

В [requests.csv](results/requests.csv) один ряд на клиентскую попытку. Расписания, исходный JSONL и логи реплик лежат рядом с каждым прогоном. Снимки PromQL сохраняются для двух одинаковых по времени наборов успешных ответов, использующих те же реплики. Графики строятся из сырья через `make report`.

Если учебный узел остановлен после замеров, запустите Docker Desktop, затем выполните `docker start mlops-hw11-control-plane` и `make overview`.

## Удаление

Остановите port-forward через Ctrl+C. Удалите кластер командой `make clean-cluster`. Приложение, контейнер узла и временные тома будут удалены. Docker сохраняет загруженные образы и локальные результаты в репозитории. Если больше не нужен образ приложения, выполните `docker image rm hw11-api:1.0.0`. Общие образы можно оставить для других работ.
